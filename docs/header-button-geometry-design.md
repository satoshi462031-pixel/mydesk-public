# 上部アイコンボタンの形状・中央配置の調査と設計

2026-10-03。対象：添付の統計画面の戻るボタン、マイページの設定ボタン。共通ヘッダー案を3つのタブ内スタックへ実装済み。

## 実装結果

- `AppStackHeader` をnative-stackの `header` へ接続し、OSのバーボタン背景を使う経路を置き換えた。戻る・動的なtitle／左右ボタン・画面optionsの配色を引き継ぐ。
- `HeaderIconButton` は押下領域44 × 44の中に円36 × 36を描く。背景のOSバージョン分岐とhitSlopを削除し、字形の補正はiconBoxに一度だけ適用する。全スタックを同時に移行したため、移行用Contextは不要。
- タイトルは左右のボタン幅を実測して中央に置く。Safe Areaのtopを明示し、背景は単色と境界線で描く。
- 設計トークン、UIルール、配置ルール、監査を更新した。監査は正常なソースの成功と、円の高さ変更／ネイティブヘッダーへの逆戻り／hitSlopの追加／アイコン行高変更の検出を確認済み。
- ブラウザー上で実際の部品を描画し、幅320／390／430、長い日英タイトル、ボタン0／1／2個、テーマ変更、消去・再表示を確認した。円と押下領域の寸法、タイトルの中央・非重複、戻る・設定・ヘルプのコールバックは正常。
- 型検査、lint、app 1052件／worker 105件のテスト、主要UI監査、iOS向けHermesバンドルの書き出しが成功。iOS実機の見た目・VoiceOver・戻るスワイプはこの環境で未確認。

以下の原因調査は実装前のコードを対象とした記録。既存の `audit:collapsible-header` は通知を隠すタイマーから離れた `scrollTo` まで正規表現が読み進み、誤検知が1件出る。HEADにも同じ通知タイマーがあり、今回のヘッダー変更では画面の収納処理を変更していない。

## 結論

背景の形とアイコンの配置を別の描画系に任せているため、現在の `44 × 44` 指定だけでは、見えている背景の正円と中央配置を保証できない。正円を要件にするなら、共通のカスタムヘッダーで背景・タップ領域・アイコンをまとめて管理する構成を推奨する。

横長の背景をアプリの `borderRadius` で修正できないことはコードから確認できた。一方、写真の下方向のずれを発生させたネイティブ階層、またはフォントのベースラインまでは、撮影時の実機ビルドを調べないと確定できない。以下では確認済みと推定を分ける。

## 写真で確認した現象

添付JPEGを変更せず、元画像591 × 1280pxのボタン領域で明度をしきい値にして外接矩形を測定した。背景はRGB各成分が20超、アイコンは180超。JPEG圧縮・背景のグラデーションを含むため概測値であり、端末のptや元スクリーンショットの物理pxには換算しない。

| 対象 | 背景の幅 × 高さ | 背景中心 | アイコン輪郭中心 | 中心差 |
| --- | --- | --- | --- | --- |
| 写真1・戻る | 約78 × 67px | (63.5, 104) | (63.5, 110.5) | 下へ約6.5px |
| 写真2・設定 | 約78 × 67px | (526.5, 104) | (526.5, 110.5) | 下へ約6.5px |

両方とも横幅が高さの約1.16倍。左右の中心は合い、上下だけ同じ量ずれている。字形ごとの光学補正だけで説明するより、共通ヘッダーの配置または共通テキスト描画の問題を先に調べるべき状態。

## コードで確認した原因と制約

1. `src/components/atoms/HeaderIconButton.tsx` は外箱を44 × 44、角丸を22にしている。しかしiOS 26以降では `OS_DRAWS_BUTTON_BACKGROUND` により自前の背景色を付けない。写真に見えるようなOS側の背景は、この角丸指定の対象外。
2. 実際の階層は `UINavigationBar → UIBarButtonItem.customView → ネイティブラッパー → RNヘッダーSubview → HeaderIconButton → iconBox → Text`。子の44 × 44は、OSが装飾する背景の外形寸法と同義ではない。既存コメントの「ガラスの背景は44ptのまま」は保証として成立していない。
3. ローカルの `react-native-screens` は4.19.0。同梱の `ios/RNSScreenStackHeaderSubview.mm` には、iOS 26向けの中央寄せラッパー、intrinsicContentSize、UIKitの制約を優先できる幅・高さ制約がある。これらはネイティブのコンパイル条件にも依存する。package.jsonだけでは端末に入っている実装やビルドSDKを証明できない。
4. `HeaderButtonGroup` は複数ボタンを1つの `headerRight` 要素として返す。React Navigation 6の `HeaderConfig.tsx` はそれを1つの `ScreenStackHeaderRightView` に包む。6ptのgapは子同士の間隔であり、OS背景を各ボタン独立の円に分割する指定ではない。
5. アイコンはフォントのText。現在は幅・高さ・lineHeightを固定済みで、光学補正も適用済み。戻る `chevron-left` の補正は24pt基準で `[0.28, 0]`、設定 `cog-outline` は表にないため `[0, 0]`。現在の補正処理は、この2つを下へ移動させていない。依存ライブラリでは `allowFontScaling: false` も既定なので、文字拡大設定を主因と断定する根拠もない。
6. `npm run audit:header-buttons` は成功する。この検査は共通部品の使用、JS側の寸法、依存バージョン宣言などを確認するもので、OS背景や実機の中心位置を検証しない。

既存の `icon-button-alignment.md` は8月時点の記録で、現在の高さ固定や光学補正を反映していない。過去の原因説明を今回の実証結果として扱わない。

写真には現在のコードにあるヘルプボタンがない。撮影時のJS、表示タイミング、ネイティブビルドの組み合わせは未特定。旧ビルドだと断定せず、実装時の比較条件に含める。

## 実装前の切り分け

同じ端末・同じビルドで、開発時のみ次の比較を行い、調査用表示は残さない。

1. iOSバージョン、アプリのビルド番号、JS更新ID、対応コミット、ネイティブ依存とビルドSDKを記録する。ネイティブ依存を替える場合は新しいdevelopment buildを用意する。
2. ヘッダーボタンの44 × 44の箱とiconBoxに中心線を表示する。本文領域にも同じアイコン・同じ箱を置いて比較する。Textを一時的に単純な小さな正方形に替えた比較も行う。
3. 中心線／正方形ごとOS背景からずれるならネイティブの配置層、箱は合うのにTextだけずれるならテキスト描画層と判定する。初回・再描画後・戻る遷移後を比較する。

写真の6.5pxをそのまま `translateY` にして直さない。写真の縮尺や原因層を無視した補正になる。

## 推奨設計：アプリが共通ヘッダーを描画する

`@react-navigation/native-stack` の既存 `header` オプションから `AppStackHeader` を描画する。既存の `@react-navigation/elements` のHeaderを土台にして、Safe Area、ヘッダー高さ、タイトルの扱いを再利用する。画面遷移を担当するnative-stackは維持する。

現在のnative-stack 6の実装では、カスタム `header` を指定するとネイティブヘッダーを非表示にし、カスタムヘッダーの実測高さをContextに渡す。したがって、OSのバーボタン背景とアプリの円を重ねずに実現できる。`headerLeft` の中にさらにネイティブヘッダーSubviewを入れたり、node_modulesを直接修正したりしない。

| 要素 | 設計 |
| --- | --- |
| タップ領域 | `UI_METRICS.headerSlotSize` = 44 × 44、縮小しない |
| 見える円 | `UI_METRICS.headerActionSize` = 36 × 36、半径18、`colors.chip` |
| 円の位置 | 44 × 44のタップ領域の中央。背景とアイコンは同じ親Viewに置く |
| アイコン | 通常22、戻る25を維持。Textの箱・lineHeightを固定し、既存の字形補正は1回だけ適用 |
| グループ | 44ptスロット間に既存の6pt gap。背景はボタンごとに描画 |
| タイトル | 画面中央。片側のボタン数が多くても中央を保ち、長い文字列はボタンに重ならない幅で省略 |
| 画面端 | `UI_METRICS.screenGutter` を使用。非対称paddingや負のmarginで補正しない |
| アクセシビリティ | 44ptの押下領域、既存の読み上げラベル・button roleを維持。隣接ボタンのhitSlop重複を避ける |

現状は `design.md` の「スロット44／見えるボタン36」に対して、部品が44の円を指定している。今回の設計ではトークン表の36／44に揃える。背景は現在のOSガラスからアプリの単色の円へ変わり、見た目は少し小さくなるが、タップ領域は維持する。

アイコン単体のずれが切り分け後にも残る場合は、ヘッダー用の描画経路だけで対応する。本文・カテゴリ・配線図のアイコンまで一括で位置を変えない。Text描画の実測なしに補正表の縦値を変更しない。

### 変更範囲

- `src/components/molecules/AppStackHeader.tsx` を追加し、現在のtitle・headerLeft・headerRight・背景色・文字色を引き継ぐ。options全体を無条件に流すのではなく、対応する項目を明示する。
- `HeaderIconButton` / `HeaderButtonGroup` の公開APIは維持する。移行時はヘッダーの描画方式をContext等で明示し、カスタムヘッダー配下ではOSバージョンによらず自前の円を描く。実機比較を通して共通ヘッダーへ移行完了後、不要な分岐を削除する。
- `RootNavigator.tsx` の共通stack optionsへ接続する。各画面の `navigation.setOptions` による動的なボタン差し替えは維持する。
- `design.md`、`icon-button-alignment.md`、UIルール、`auditHeaderButtons.ts` の「OS背景を正円とみなす」前提を更新する。
- まずMyPage／GadgetStatsで実機比較し、その後共通optionsを使う3スタックへ適用する。公開デスクとマイデスクは同じヘッダー経路で確認し、公開デスク固有の背景・文字色も引き継ぐ。

画面遷移の機構は維持できるが、ヘッダータイトルのネイティブ固有アニメーションやLiquid Glassの表現は変わる。戻るスワイプの動作と遷移中の見え方は実機で確認する。

### 代替案

Liquid Glassを優先するなら、互換性を確認したReact Navigationの更新とネイティブの個別bar button APIへの移行を別途設計する。その場合はOSの形状・余白に従うため「常に正円」を契約にしない。現在のNavigation 6には、screensの `hidesSharedBackground` を通常の画面optionsから渡す経路がないため、最新ドキュメントの設定をそのまま追加する案は採らない。

## 受け入れ条件

- iOS 26系実機で戻る・設定・ヘルプ、および右側複数ボタンを確認する。対応する旧iOSでも同じ自前の円になることを確認する。
- 静止状態の円の幅と高さが一致する。スクリーンショットのアンチエイリアスを含む測定誤差は1物理px以内とする。
- 円とiconBoxの中心はレイアウト上で一致する。戻る・設定の輪郭中心は見える円の中心から1物理px以内を目安に確認する。非対称アイコンの見た目は既存の光学補正も含めて判断する。
- 初回表示、プロフィール更新、言語・テーマ切り替え、フォント読み込み後、別画面から戻った後でも位置が変わらない。
- 単一・複数ボタン、長い日英タイトル、小さい画面、文字サイズ拡大、VoiceOver、戻るスワイプ、押下先を確認する。
- `typecheck` とUIルールに定めた監査を実施する。静的監査の成功だけで視覚検証完了にしない。
