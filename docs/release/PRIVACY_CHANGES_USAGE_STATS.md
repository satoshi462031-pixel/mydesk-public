# プライバシー関連の確認事項（ガジェット利用統計）

`docs/metrics/GADGET_USAGE_STATS.md` の実装に伴う、プライバシーポリシーと
App Store Connect の App Privacy への影響。

**公開文書はまだ変更していない。** 反映は本人の判断で行うこと。

---

## 結論

**App Privacy の申告変更は不要。プライバシーポリシーも、確認のうえ必要なら1行の追記で足りる。**

理由：新しいデータ収集をしていない。集計対象は利用者が既に公開したデスクの情報だけで、
アプリから外部へ送る項目は1つも増えていない。唯一の追加は、公開処理が
`share_snapshot` に書く `snapshotCapturedAt`（そのスナップショットを作った時刻）で、
これは既に保存しているデータへのタイムスタンプ1つ。

---

## 1. 何が増えたか

| | 変更 |
|---|---|
| 端末から送信する項目 | 増えていない |
| 第三者提供先 | 増えていない（PostHog へは送らない。集計は既存の Supabase 内で完結） |
| 保存する項目 | `desks.share_snapshot.snapshotCapturedAt`（publish 時刻）が1つ増える |
| 利用者に求める操作 | 無し（同意ダイアログもアンケートも無い） |

`snapshotCapturedAt` は、利用者が自分で「公開する」と決めた操作の時刻。
公開デスクの `created_at` / `updated_at` を既に保存していることと同種で、
新しい種別の個人情報にはあたらない。

## 2. プライバシーポリシーの確認

現行の `docs/release/PRIVACY_POLICY_JA.md` について、以下を確認する。

- **「3.3 公開・共有機能に関する情報」** が、公開デスクの内容をサービス改善や
  統計の目的で利用しうることを含んでいるか
- **「6. 利用目的」** に、公開情報の統計的な集計・分析が含まれているか

含まれている場合は変更不要。含まれていない場合のみ、6 へ次の1行を追記する案：

> - 公開された デスク情報を、個人を特定しない統計として集計し、サービスの改善および
>   利用者向けの参考情報の作成に利用すること

### 変更が不要な範囲

- 3.6（PostHog への分析情報）— 触っていない
- 7（外部サービス）— 提供先は増えていない
- 11（保存期間）— 公開デスクを非公開化・削除すれば集計対象から外れる（既存の挙動どおり）
- 13（利用者の選択）— デスクを非公開にすれば母集団から外れる。新しいオプトアウトは不要

## 3. App Store Connect の App Privacy

**変更不要。** 新しいデータ種別の収集も、新しい目的での利用も発生していない。
公開デスクの内容は既に「利用者が作成したコンテンツ」として扱われており、
その集計は収集項目を増やさない。

提出前に、既存の申告が「公開デスクの内容」を正しくカバーしていることだけ確認する。

Google Play の Data safety も同様に変更不要（初回リリースでは Android を出さない）。

## 5. 将来、収集を増やす場合

使用頻度・満足度・再購入意向・撤去理由を取りたくなったら、それは**新規収集**にあたる。
そのときは以下がすべて必要になるため、リリース前にやらないこと。

- 既存の分析同意（`@analytics_consent`、PostHog 用）とは**別の同意**の新設
- プライバシーポリシーへの収集項目・保存期間・撤回方法の記載
- App Store Connect の App Privacy 更新（仮名化していても
  「Not Linked to You」とは申告しない。同一利用者から同じ識別子を再計算できる設計になるため）
- 撤回時とアカウント削除時の削除導線
