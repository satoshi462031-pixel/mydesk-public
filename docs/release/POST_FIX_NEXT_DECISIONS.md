# 審査対応修正後に考えること

更新日：2026年9月25日

## 実装済み・反映待ち

次の項目はリポジトリへ実装済みです。本番反映にはビルドまたはデプロイが必要です。

- Androidの録音権限を明示的にブロック
- PostHog分析を初期オプトアウトへ変更
- AI初回送信前にAnthropicへの送信内容と目的を表示し、明示同意を保存
- AI回答ごとの「危険・不適切」「誤情報」通報
- AI回答通報テーブルとRLS
- AIシステムプロンプトへ危険・違法・個人情報・安全性の制約を追加
- 公開デスクのメールアドレス、リンクスパム、明白な禁止テキストの事前検査
- クライアント迂回時も拒否するPostgresトリガー
- 24時間以内の一次確認を定めたモデレーション運用手順
- iOS／Androidで異なる自動更新説明
- ウェブのアカウント削除申請ページ
- オンボーディング終了時の分析の選択画面（許可する／許可しない）
- 公開デスクの閲覧数・購入リンクを開いた数を、人を識別しない日別件数として同意と無関係に記録（migration 091、worker、アプリ）。`/admin/community` の「共有の閲覧と購入リンク」で見る

## リリース前に決めること

### 1. 配信国（2026年9月25日決定）

**ヨーロッパ以外へ配信する。** 次の国・地域は App Store Connect の配信国から外す。

| 除外 | 理由 |
|---|---|
| EU/EEA・英国・スイス | GDPR / UK GDPR / スイス FADP。分析・AI 送信に同意の根拠と越境移転の手当てが要る |
| 中国本土 | App Store での配信に ICP 届出、AI 機能に生成AIサービスの当局登録が要る |
| 韓国（初回のみ） | 個人情報保護法が国外移転（PostHog・Anthropic・Supabase）に個別の同意を求める。今の同意導線では足りない |

残る決定事項：

- 未成年者の最低利用年齢。米国を含むので 13 歳以上にして COPPA の対象外にする（推奨）
- 米国の州ごとの年齢確認法の状況を提出直前に確認する

**購入リンクの海外対応（未着手）**：購入リンクは amazon.co.jp のアソシエイトタグで出している。海外の利用者が押しても日本の Amazon に着くため、海外からのアフィリエイト収益はほぼ無い。米国 Amazon アソシエイトの登録（運営者の作業）と、利用者の地域で amazon.com へ切り替える実装が要る。

### 1-2. 立ち上げ時の公開デスク（未定）

みんなのデスクが空だと共有の価値が伝わらない。公開前に入れておく件数と、依頼する相手を決める。

案：30件（フィードを2〜3回スクロールしても尽きない量）。自分と知人で10件、X・note のデスクツアー投稿者へ個別に依頼して20件。依頼の条件は、共有リンクを本人の投稿に貼ってもらうこと。公式デモ（`demoDesks.ts`）は実在の人のデスクではないのでフィードへ混ぜない。

### 1-3. 主な指標（未定）

案：次の3つを週ごとに見る。

| 指標 | 見る場所 | 同意の影響 |
|---|---|---|
| 公開デスク数（供給） | `/admin/community` のユーザーと公開 | 無し（DB の件数） |
| デスクの閲覧数（集客）。うち共有リンクを Web で開いた数 | `/admin/community` の共有の閲覧と購入リンク | 無し（091） |
| 閲覧あたりの購入リンクを開いた割合（収益） | 同上 | 無し（091）。他人のデスクのガジェット詳細から開いた分だけ数える |

閲覧数は人を識別しないので、同じ人が開き直した分も重ねて数える。リンクのプレビュー取得（X・iMessage・Slack など）と、持ち主自身のアプリでの閲覧は除く。

### 2. 運営者情報

法務ページには現在、既存実装に合わせて「法令に基づく請求があれば開示」と記載しています。App StoreのSupport URL、特定商取引法その他の適用関係を確認し、必要なら実名、住所、電話番号を公開してください。

決定事項：

- 個人名または屋号
- 住所と電話番号の公開方法
- 問い合わせへの回答期限と休日
- 個人事業の開業・税務処理

### 3. AI通報の担当者と処理方法

通報機能を置くだけでは審査要件を継続的に満たせません。毎日確認できる担当者と、対象回答を改善へ反映する経路が必要です。

決定事項：

- `ai_response_reports`と`desk_reports`を毎日確認する担当者
- 重大通報の通知先
- 誤検知、危険出力、反復出力の記録方法
- モデルまたはシステムプロンプトを変更する判断基準
- 通報者へ個別返信するか

### 4. 画像モデレーション

今回追加したのは公開テキストの検査です。公開写真の自動判定は未実装です。利用者数が少ない初期は、公開時の注意表示と通報後24時間以内の目視確認で運用できます。投稿数が増える前に画像モデレーションAPIの導入を判断してください。

推奨導入条件：

- 1日20件を超える新規公開
- 重大な画像通報が1件でも発生
- 審査から事前画像フィルタを具体的に要求された場合

### 5. 分析データの同意導線

主要な指標（閲覧数・購入リンク）は 091 で同意と無関係に取れるようになった。PostHog は画面遷移や機能の使われ方など、それより細かい行動を見るためのもの。

分析は初期オプトアウトへ変更しました。オンボーディングを抜けるとき（どの出口からでも、ログインの前）に「許可する／許可しない」の選択画面を一度だけ出す（`AnalyticsConsentModal`、2026年9月25日実装）。2つのボタンは同じ大きさで、拒否しても主要機能は使える。あとから設定画面で変更できる。

既にオンボーディングを済ませた端末（TestFlight の利用者など）には出ない。設定画面でしか選べない。

決定事項：

- 分析しない状態で判断できるプロダクト指標
- PostHogの保存リージョンと保存期間
- ウェブ側Vercel Analyticsを継続するか

### 6. AIデータの保存と契約条件

利用者へ「運営者は独自のモデル学習へ利用しない」と説明しています。Anthropic APIの契約プラン、保存期間、学習利用の有無、サーバーリージョンがこの説明と一致することを本番契約で確認してください。

決定事項：

- Anthropicの本番契約とデータ保持設定
- AI障害調査用ログへ本文を残すか
- AI通報時に直前プロンプトを保存する期間
- 利用者がAI通報データの削除を請求する方法

### 7. 課金と価格

コード上のフォールバック価格は月額590円、年額5,900円です。実際にはストア価格を表示します。App Store Connect、Play Console、RevenueCatで商品ID、権利、価格、請求期間が一致する必要があります。

決定事項：

- 月額・年額価格
- 無料体験の有無
- 年額割引表現
- 値上げ時の通知手順
- アカウント削除前に購読管理を強制確認させるか

### 8. データ保持期間

分析データは1年、バックアップは最新7世代としています。通報、サーバーログ、問い合わせ、課金イベントについて具体的な保存期間を決め、プライバシーポリシーと実際の削除ジョブを一致させてください。

### 9. ストア申告

Privacy Nutrition LabelとData safetyは、リリース候補ビルドの実通信を確認してから入力してください。特にPostHog、RevenueCat、Supabase、Anthropic、Vercel Analyticsが生成する識別子と位置推定の扱いを確認します。

### 10. デプロイ順序

1. Supabase migration 037と038、091を適用（091 を worker より先に入れる。後だと Web の閲覧が数えられずに捨てられる）
2. `ai-coach` Edge Functionをデプロイ
3. Landingをデプロイし、`/account-deletion/`を外部回線から確認
4. App Store / Google Playの法務URLと削除URLを設定
5. iOS / Androidのリリース候補を生成
6. AndroidManifestに録音権限がないことを確認
7. AI同意、AI通報、UGC拒否、アカウント削除、購読復元を実機確認
8. 審査用アカウントとReview Notesを登録して提出
