2026-10-16。対象は作業ツリーの検証基盤修正。**本番状態は未照会・配布確認は未実施**。コードに対策があることと、その対策が本番で有効なことを別々に記録する。

## ローカル／CIの検証

```sh
npm ci
npm --prefix worker ci
npm run check
npm run typecheck:edge
```

`check`はApp.tsxを含む型検査・lint、テストの型検査、アプリテスト、PGlite上のDB検証、Workerの単体／workerdテストを実行する。`typecheck:edge`はDeno 2.9.6を使い、Edge Functionの全index.tsを実行せず型検査する。CIでも同じ検証を行う。Denoは[公式手順](https://docs.deno.com/runtime/getting_started/installation/)で用意する。

PGliteの検証は必要な既存スキーマを再現してマイグレーションを実行する。Supabase全体の再構築や、独立した複数接続の競合を検証するものではない。Workerの実行環境検証は本番の設定・Secret・バインディングを使わない。

## 公開後の品質と価値

初回成果への到達率と翌週再利用率は`docs/metrics/README.md`の同じ母数・観測期間で保存する。保存・復元・公開の失敗、クラッシュ、AI・画像の費用は週次で確認する。個人の入力文・写真を追加で収集しない。

起動・配線図生成・画像表示の時間は、端末・OS・機材数・写真数・アプリ版を固定して記録する。PCのNodeベンチ結果を実機の応答時間として使わない。まず初回の実測値を保存し、次の変更で比較する。
