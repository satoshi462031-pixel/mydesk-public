# iOSプッシュ通知

2026-10-07。実装を準備し、公開スイッチはオフにしておく。

## 通知する内容

| 種類 | タイトル | 本文例 | 条件・頻度 |
|---|---|---|---|
| フォロー中の人の初回公開 | 投稿者名 | 新しいデスク「仕事のデスク」を公開しました | 公開デスク・公開プロフィールのみ |
| フォロー中の人の更新 | 投稿者名 | 「仕事のデスク」を更新しました | 機材・写真の変更のみ。同じデスクから12時間に1回まで |
| 自分のデスクへの拍手 | 拍手が届きました | 「仕事のデスク」に新しい拍手が3件届きました | 最初はすぐ、同じ持ち主へ12時間に1回まで |

- 通知を押すと対象の公開デスクを開く。端末の登録言語に合わせて日本語・英語を切り替える。
- フォロー通知は全体の設定と相手ごとの設定を両方確認する。ブロック関係にある人へは送らない。
- 拍手の件数は、前の通知以降に対象デスクへ届いた分。初回は直近24時間だけを数える。
  本人・ブロック関係にある人の拍手は除き、拍手した人の名前は出さない。
- 拍手の再通知は12時間経過後の新しい拍手をきっかけに送る。タイマーによる後追い配信は行わない。
  持ち主単位の送信記録を使うため、複数デスクを横断した全件のダイジェストではない。
- 同じ内容の再公開・文章だけの変更・URL限定公開はフォロー通知の対象外。
- 音はシステムの既定。アプリを開いている間はバナー・通知一覧に表示し、音・バッジは出さない。

## 非公開時の制御

- アプリの `src/constants/features.ts` にある `PUSH_NOTIFICATIONS_ENABLED = false` で、
  通知設定の入口・相手ごとの通知ボタン・通常の許可ダイアログ・トークン登録・送信要求・前景表示を止める。
  通知設定へ直接遷移しても設定の一覧を表示する。
- サーバーの `PUSH_NOTIFICATIONS_ENABLED` が文字列 `true` 以外なら、
  `notify-followers` / `notify-claps` はDBや送信記録に触れず、`feature_disabled` を返す。
  古いアプリからの要求も止められる。
- ログアウト時の登録済みトークン解除は継続する。
- 開発ビルドの既存の「通知許可をデバッグ」はOSの許可だけを確認する。トークン登録・送信は行わない。
- アプリ内の「更新」一覧・フォロー・拍手自体は引き続き利用できる。

## 公開するとき

1. DBの085・096と、更新日時・拍手の版を管理する既存マイグレーションの適用を確認する。
2. サーバーのスイッチをオフにした状態で `notify-followers` / `notify-claps` をデプロイする。
   共通の文面は `supabase/functions/_shared/notificationContent.ts` に置く。
3. Expo のアクセストークンで送信を縛る。Expo の既定では、宛先トークン（`ExponentPushToken[...]`）を
   知っていれば誰でもその端末へ通知を送れるため、`push_tokens` が漏れると偽の通知の踏み台になる。
   1. expo.dev の Access tokens でロボット用トークンを作り、`npx supabase secrets set EXPO_ACCESS_TOKEN=...` で設定する
      （関数は値があれば `Authorization: Bearer` を付けて送る）。
   2. そのあとで、プロジェクト設定の「Enhanced Security for Push Notifications」を有効にする。
      順番を逆にすると、その間の通知がすべて拒否される。
4. iOS実機で通知許可・宛先登録・2種類の文面・タップ先・設定による停止を確認してから、
   アプリとサーバーの両方の `PUSH_NOTIFICATIONS_ENABLED` を有効にして公開する。

この変更で本番のデプロイ、Secretの変更、DB適用、EASビルドは実施していない。
